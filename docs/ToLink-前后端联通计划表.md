# ToLink 前后端联通计划表

> 文档版本：1.3
> 更新日期：2026-05-11（接口全量扫描后更新进度）
> 适用范围：`toLink-Web` 与 `toLink-Service` 联调推进、缺口追踪、阶段验收

---

## 一、目标说明

本计划用于把当前前端项目与后端项目逐步联通，避免“页面先写、接口再猜”的开发方式。

整体目标分为三层：

1. 先打通基础认证链路，保证用户能进入系统。
2. 再打通知识库、文件、对话等核心业务闭环。
3. 最后补齐编辑能力、异常处理、体验细节和接口缺口台账。

---

## 二、联通原则

### 2.1 总体原则

1. 先做基础链路，再做业务模块。
2. 每个模块都要经过“接口确认 -> 前端接入 -> 联调验证 -> 缺口记录”四步。
3. 优先完成“列表、创建、详情”闭环，再补“编辑、删除、优化”。
4. 所有缺失接口统一记录在 `docs/ToLink-缺失接口清单.md` 中。
5. 联通过程中发现前端需要但后端未实现的接口，必须当天写入缺失接口清单。
6. 缺失接口一旦后端实现并完成前端适配，必须从缺失接口清单中删除，不保留已解决项。

### 2.2 每个模块的标准动作

每个模块都按下面节奏推进：

1. 确认后端真实接口、请求字段、响应字段、错误码。
2. 更新前端 `types`、`services`、状态管理和页面逻辑。
3. 用真实后端服务做联调验证。
4. 把缺失接口、字段不一致、状态定义差异记入文档。

### 2.3 缺口清单维护规则

`docs/ToLink-缺失接口清单.md` 是当前仍待后端补充的接口台账，不作为历史归档使用。

维护规则：

1. 联调时发现后端未提供的接口，立即新增到缺失接口清单。
2. 新增记录必须包含前端位置、期望接口、建议请求体、建议返回体、后端现状和影响。
3. 后端接口实现后，先核对 Controller 路径、请求字段和响应字段。
4. 前端完成接入并通过基础验证后，从缺失接口清单删除该记录。
5. 已实现但前端尚未适配的问题，不放入“缺失接口”，应写入当前模块交接或联通计划的待办说明。

### 2.4 验收标准

每个模块至少满足以下条件：

1. 页面能发起真实请求。
2. 页面能正确展示成功结果。
3. 页面能正确处理失败结果。
4. 刷新后状态不丢失或行为符合预期。

#### 当前阶段重点

本阶段重点确认以下内容：

1. 登录请求字段是否与后端完全一致。
2. 注册字段校验是否与后端限制一致。
3. 登录后是否必须立即调用用户资料接口。
4. 退出后是否彻底清除本地认证状态。

#### 阶段 1 前端验证清单

前端验证时建议按下面顺序操作：

1. 打开欢迎页，确认默认停留在未登录状态。
2. 使用一个全新用户名完成注册。
3. 注册成功后确认是否自动进入系统首页。
4. 刷新页面，确认登录态仍然存在。
5. 退出登录，确认页面回到欢迎页。
6. 使用刚注册的账号再次登录，确认能重新进入系统。
7. 登录失败时检查提示是否准确，例如密码错误、用户名不存在。
8. 注册失败时检查提示是否准确，例如用户名已存在、邮箱已被使用、两次密码不一致。

#### 阶段 1 验收标准

满足以下条件即可认为阶段 1 完成：

1. 注册成功后能自动进入系统。
2. 登录成功后能正确加载用户资料。
3. 刷新页面后登录态不会立即丢失。
4. 退出登录后会回到欢迎页，且受保护页面不可直接访问。
5. 登录和注册失败时，前端能展示清晰错误信息。

## 五、建议执行顺序

建议严格按以下顺序推进：

1. 认证模块
2. 用户资料模块
3. 知识库模块
4. 文件模块
5. 对话模块
6. 配置与收尾

这样安排的原因：

1. 后续所有业务页面都依赖登录态。
2. 知识库是文件和对话的上游。
3. 文件处理完成后，对话才真正有内容可问。

## 七、当前阶段结论

现阶段最合适的推进方式是：

1. 先把认证模块完全联通并重启后端做真实验证。
2. 然后处理用户资料模块。
3. 再进入知识库列表、新建、删除这三个核心闭环。

后续执行时，严格按本计划逐项推进，每完成一个子项就做真实联调和文档同步。
